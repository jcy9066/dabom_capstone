# BNO055 IMU 및 위험 상황 TTS 음성 안내 추가 계획

> 작성: 2026-11-04 · 상태: **Draft / 범위 정의** · 대상: DABOM AI 자율순찰 로봇
>
> 본 문서는 신규 기능의 요구사항·인터페이스·검증 기준을 확정하기 위한 작업 명세입니다. **IMU 드라이버, 실제 TTS 음성 송출 및 위험 감지 자동 연결은 아직 구현·실기기 검증되지 않았습니다.**
> 원본 PR #96 / 후속 PR #97의 모터·Nav2 안전 계약을 변경하거나 병합하지 않습니다.

## 1. 현재 시스템 및 변경 범위

- Raspberry Pi 4에서 ROS 2 Humble, `/wheel_ticks`, `/odom`, Nav2·AMCL 및 LiDAR 사용
- Pico W GP16은 **PWM 비프음 전용**으로 구현되어 있으며, `BEEP` / `VOLUME` 명령과 대시보드 경고 패턴이 이미 존재함
- 현재 `raspberry/controllers/speaker_controller.py`의 `speak(text)`는 문자 로그 출력뿐이며 실제 음성 합성이 아님
- 위험 감지는 GPU 서버의 RTMO-M + BoT-SORT + X3D-M 파이프라인에서 처리하며 웹 관제/알림 경로가 존재함
- 본 PR의 두 신규 범위: **(A) BNO055 IMU 센서 데이터 연동** + **(B) 확인된 위험 상황에서 로봇의 TTS 음성 안내**

## 2. A — BNO055 IMU 연동

### 목표

1. Raspberry Pi 4에 BNO055를 I²C로 연결하고 인식·초기화·재연결 상태를 진단
2. 방향(quaternion), 각속도, 선형가속도, 교정 상태를 읽고 비정상값/오래된 데이터를 차단
3. ROS 2 `sensor_msgs/msg/Imu`로 `/imu/data` 발행 (기본 `frame_id=imu_link`)
4. IMU와 로봇 차체의 **물리적 장착 방향**을 명시하고, 필요한 `base_link → imu_link` 정적 TF 설정
5. Wheel Odometry / AMCL / Nav2 기존 경로를 유지하며, IMU 기반 yaw 융합은 **별도 보정·실주행 검증 후** 활성화

### 연결 및 검증 시 주의

- BNO055 모듈의 보드별 VIN/VDD 및 I²C **3.3V 논리 수준**을 확인하고 Pi의 SDA/SCL과 연결 (Pico GP16 비프음 배선과 독립)
- I²C 주소(통상 `0x28` 또는 `0x29`), 버스, 전원 및 GND 확인; 특정 배선이 완료된 것으로 가정하지 않음
- 센서 부재/미교정/NaN/timeout 시 navigation-ready로 위장하지 않고 상태 노출
- 기본 odom→base_link TF 발행자는 기존 wheel_odometry가 유지; 동일 TF를 다른 노드가 중복 발행하지 않음
- 정지·전진·회전 시 방향 부호, 드리프트, 교정 유지, ROS timestamp 및 프레임 정합 검사

## 3. B — 스피커 및 위험 상황 TTS 음성 안내

### 하드웨어·오디오 경로

- **기존 Pico GP16의 비프음 출력은 유지.** PWM 경고음 출력만으로는 한국어 TTS 음성 재생이 불가능하므로 이를 TTS 성공으로 취급하지 않음
- 실제 음성은 Raspberry Pi의 **독립적인 오디오 출력(USB 오디오 또는 검증된 I²S DAC/증폭기+스피커)** 사용을 우선 검토
- TTS 엔진은 현장에서 동작하는 **한국어 지원 오프라인 엔진/음성 모델**을 선택하고 별도 설치·발음·재생 장치 점검
- 기존 대시보드 BEEP·VOLUME·10초 LED/경고 패턴의 계약을 변경하지 않으며, TTS 음량은 실제 출력 장치와 연동

### 이벤트 흐름

```text
GPU Server: RTMO-M + BoT-SORT + X3D-M
   → fresh/confirmed danger 판단 (stale·중복·낮은 신뢰도 차단)
   → 사건 단위 중복 제거 + 쿨다운 + 로봇 상태 확인
   → 인증된 서버→Pi 명령 채널로 TTS 경고 요청
   → Pi: 비동기 한국어 TTS 생성·재생 / 취소·타임아웃
   → 시작/완료/실패 ACK 및 관제 로그
```

### 기본 경고 문구

> 위험 상황이 감지되었습니다. 주변 안전을 확인하고 안전한 거리를 유지해 주세요.

- 모델 판정은 오탐 가능성이 있으므로 **'폭행이 확정되었습니다'라고 단정하지 않음**
- 모델/클라이언트 입력을 그대로 음성 출력하지 않고 **허용된 고정 경고 문구**만 재생
- 프레임마다 연속 송출하지 않도록 사건별 dedupe 및 설정 가능한 쿨다운 적용
- 첫 경고 시 자동 재생; 별도 수동 경고 명령의 권한·우선순위는 기존 경고 기능과 충돌하지 않도록 정의
- 통신 단절/오디오 장치 없음/엔진 실패 시 **모터 제어에 영향 없이** TTS 실패 상태만 기록
- E-STOP·취소·종료 시 음성 재생을 중지할 수 있도록 설계; 음성 처리 때문에 STOP ACK/Encoder 검증·Nav2 콜백을 지연시키지 않음
- 원격에서 전달되는 임의 텍스트, 명령어, 셸 인자를 실행하지 않음

## 5. 완료 조건 / 제한

- 실기기에서 BNO055가 ROS IMU 메시지를 유효한 timestamp·frame_id로 발행하고 자세 변화가 측정과 부합해야 함
- **실제 위험 감지 → Pi 스피커 한국어 음성 송출 → 관제 결과 로그**를 현장에서 검증해야 함

- 현재 단계는 기능 범위 문서 작성이며, **실제 센서/오디오 동작 완료, full pytest PASS 또는 병합 가능 판정이 아님**
